# 自動化と外部連携

## 自動化ルール

「きっかけ」が起きたら「動作」を自動で行います。ワークスペースの「⋯ 操作」→「⚙ 自動化ルール」（編集権限が必要）。

### 例

| やりたいこと | きっかけ | 動作 |
| --- | --- | --- |
| レビューを依頼したら所有者に知らせる | 状態が「レビュー中」になった | 所有者に通知 |
| 期限の前日に担当者に知らせる（完了は除く） | データベースの日付の1日前（状態が完了なら除く） | 項目のユーザーの列（担当者）に通知 |
| 社外向けのページを Slack に流す | ラベル「社外」が付いた | 外部への通知（Slack） |
| 問い合わせが来たら担当チームに知らせる | ページが作られた（対象: 問い合わせのページの下） | 指定した人に通知 |
| 完了したら状態を公開済みにする | データベースの値（状態）が「完了」になった | 状態を変える |

### きっかけ

- **ページの状態が変わったとき**（変わった先の状態を指定できます）
- **ラベルが付いたとき**
- **ページが作られたとき**
- **データベースの値が変わったとき**（データベース・列・値を指定）
- **データベースの日付になったとき**（日付の列の◯日前・当日・◯日後。1時間ごとに確認し、同じ項目・同じ日付には1回だけ動きます。「状態が完了なら除く」などの条件も付けられます）

「対象」でページを選ぶと、そのページの下で起きたことだけに絞れます。

### 動作

- **通知する**: ページの所有者・ウォッチしている人・指定した人・データベースのユーザーの列（例: 担当者）。画面内とメールに届きます。
- **外部へ送る**: 下の「外部への通知」で登録した送り先へ。
- **状態を変える**・**ラベルを付ける**

文面には `{title}`（ページ名）・`{actor}`（操作した人）・`{date}`（日付）・`{status}`（状態）を使えます。例: `「{title}」のレビューをお願いします（{actor}さんより）`

ルールの一覧で、有効／無効の切り替え、最後に動いた日時・回数・エラーを確認できます。動作で変わったページで、ほかのルールが続けて動くことはありません。

## 外部への通知（Slack・Teams・Webhook）

ワークスペースの出来事を、チャットなどに送ります。「⋯ 操作」→「📣 外部への通知」（編集権限が必要）。

1. 「＋ 送り先を追加」で形式を選び、URL を貼り付けます。
   - **Slack**: Slack の「Incoming Webhook」の URL。
   - **Microsoft Teams**: チャネルの「ワークフロー」で「Webhook 要求を受信したらチャネルに投稿する」を作り、その URL。
   - **JSON**: 任意のシステムへ。署名（`X-Skiwi-Signature`）で送り元を確かめられます（秘密の値は作成時に一度だけ表示）。
2. 送る出来事を選びます: ページの作成・更新（編集が落ち着いてからまとめて）・削除、コメント、ゲスト向けの公開。
3. 「テスト送信」で届くか確かめます。

権限を絞ったページ（共有設定で「引き継がない」にしたページとその下）の出来事は送りません。

## 受信用の Webhook（外からページを作る）

フォーム・監視ツール・問い合わせ窓口などから、skiwi にページやコメントを作らせます。「⋯ 操作」→「📥 受信用の Webhook」。

1. 「＋ 受信用の URL を作る」で、動き方と受け取り先のページを選びます。
   - **データベースに項目を追加**（受け取り先はデータベース）
   - **子ページを作る**
   - **コメントを付ける**
2. 作成すると URL が一度だけ表示されます。送り元のツールに設定します（送り方の例も表示されます）。
3. URL に JSON を POST すると、作った人の権限で項目・ページ・コメントができます。

```
{ "title": "ログインできない", "text": "本文（改行で段落）", "values": { "状態": "未対応", "期限": "2026-12-01" } }
```

- `values` は列名（または列のID）と値。選択肢は名前、ユーザーはメールアドレスでも指定できます。
- Slack 形式の `{ "text": "…" }` もそのまま受け付けます。
- 1分に60件・本文64KBまで。URL が漏れたときは「URLを作り直す」で古い URL を無効にします。

## skea のタスクを表示する（skea 連携）

管理者が [skea 連携を設定](/help/admin#skea連携の設定) していると、本文に書いた skea のタスクID（`SKEA-123` のような「プロジェクトキー-番号」）が、自動で skea のタスクへのリンクになります。本文の文字は書き換えません（表示だけ）。そのため、前から書いてあるページにもそのまま効きます。

1. 画面右上の自分のアイコンのメニューの「🔗 skea と連携」を押します。
2. skea の画面で内容を確認して「許可」を押すと、元のページに戻ります。
3. タスクIDの横に、タスクのタイトルと状態（色付き）が出るようになります。

- **開き方**: 閲覧中はタスクIDをクリックすると、skea のタスクが新しいタブで開きます。編集中のクリックはカーソルを置くだけなので、**Ctrl+クリック（Mac は ⌘+クリック）** するか、横のタイトル（連携していないときは「↗」）をクリックします。
- タイトルと状態は、**あなた自身の skea の権限** で読みます。skea で見られないタスクは、リンクだけになります。表示は1分ほど覚えておくので、skea で変えた内容が出るまで少しかかることがあります。
- 連携していない人には、リンクだけを表示します（タイトルは出ません）。
- 対象は、管理者が決めたプロジェクトキーだけです。コードブロックとインラインのコードの中は対象外です。ゲスト向けの公開ページでは何も変わりません。
- 連携をやめるときは「🔗 skea 連携中（解除）」を押します。skea の API キーの画面から失効させても、連携は外れます。

## skawau のファイル名を表示する（skawau 連携）

管理者が [skawau 連携を設定](/help/admin#skawau連携の設定) していると、本文に貼った skawau のファイル・フォルダのリンクに、ファイル名が出ます。本文の文字は書き換えません（表示だけ）。

1. 画面右上の自分のアイコンのメニューの「🔗 skawau と連携」を押します。
2. skawau の画面で内容を確認して「許可」を押すと、元のページに戻ります。
3. 貼り付けたままの URL は、閲覧中は「📄 見積書.xlsx」のようにファイル名だけになります。編集中は URL の後ろに名前が添えられます。

- 「資料」のように文字を付けたリンクは文字のまま表示し、マウスを乗せるとファイル名が出ます。
- ファイル名は **あなた自身の skawau の権限** で読みます。見られないファイルは URL のままです。連携していない人にも URL のまま表示します。
- 連携をやめるときは「🔗 skawau 連携中（解除）」を押します。skawau の APIキーの画面から失効させても、連携は外れます。

## smohua のフォームの回答を表示する（smohua 連携）

管理者が [smohua 連携を設定](/help/admin#smohua連携の設定) していると、smohua（フォーム）で集めた回答を、ページの中に表示できます。

1. 画面右上の自分のアイコンのメニューの「🔗 smohua と連携」を押し、smohua の画面で「許可」を押します。
2. ページを編集して `/` を打ち、「フォームの回答（smohua）」を選びます。
3. 表示したいフォームの URL（smohua のフォームの画面の URL）を貼り付けます。

- ブロックには「集計」（選択肢ごとの件数・平均・記述）と「一覧」（新しいものから50件）があります。「↻」で読み直せます。
- 回答は **見ている人自身の smohua の権限** で読みます。そのフォームの持ち主でも編集できる人でもない人には、回答は表示されません。
- 連携していない人には「smohua と連携」への案内が出ます。ゲスト向けの公開ページでは、回答は表示されません。
- 回答はページには保存しません（ページの履歴や書き出しには入りません）。

## API

ほかのシステムから skiwi を操作できます。画面右上の自分のアイコンのメニューの「API の説明書」で、使える API・送る内容・応答・curl の例を確認でき、「試す」でその場で実行できます。

- 認証: 画面右上の自分のアイコンのメニューの「APIトークン」で発行したトークンを `Authorization: Bearer <トークン>` で送ります。
- トークンは「読み取り専用」か「読み書き」を選べ、期限を付けられます。不要になったら失効させてください。
- API でできることは、トークンを発行した人の権限の範囲に限られます。

## AI から使う（MCP）

Claude などの AI のツールから、MCP（Model Context Protocol）で skiwi を使えます。AI がページを探して読んだり、ページやコメントを作ったり、データベースに項目を足したりできます。

- 接続先: `https://（skiwi のアドレス）/mcp`
- 認証: 上の API トークンを `Authorization: Bearer <トークン>` で送るように設定します。AI に読ませるだけなら「読み取り専用」のトークンにすると安心です。
- できること: 検索、ページの一覧・本文（Markdown）・被リンク、ページの作成、本文の書き換え（全部・見出しの節だけ・末尾への追記）、名前や状態の変更・移動・ゴミ箱へ移す、ラベル、コメント、データベースの列と項目、自分の ToDo
- 本文を書き換える前の内容は版として残るので、ページの「履歴」から戻せます。開いている人の画面にもすぐ反映されます。
- データベース・ホワイトボードなど、Markdown で表せないブロックは、書き換える範囲に入れると消えます。
- AI の操作は、トークンを発行した人の操作として監査ログに残ります。
