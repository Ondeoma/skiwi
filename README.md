# skiwi

<p align="center"><img src="frontend/public/logo.svg" width="128" height="128" alt="skiwi のロゴ"></p>

skiwi は、チーム向けの Wiki です（ブロックエディタ、同時編集、OIDC認証）。設計は [docs/design.md](docs/design.md)。ライセンス: MIT

## 構成
| モジュール | 内容 |
|---|---|
| `modules/core` | ドメインモデル、権限解決(`Acl`)、並び順(`FractionalIndex`) — 純粋ロジック |
| `modules/db` | doobie + Flyway。スキーマ(`V1`〜`V11`)と `Store` / `DocStore` / `OpsStore` / `ScimStore` / `DatabaseStore` |
| `modules/auth` | OIDC (Authorization Code + PKCE) クライアント |
| `modules/storage` | 添付ファイルの保存先（S3互換ストレージ。開発は ScalaS3） |
| `modules/notify` | メール通知（`mail_outbox` を送信するワーカー、SMTP） |
| `modules/api` | http4s ルート（`/auth/*`, `/api/*`、検索、添付、版履歴、APIトークン、監査ログ、`/scim/v2`）、Cookieセッション／Bearerトークン |
| `modules/collab` | 同時編集サーバー: WebSocketリレー、updateログの永続化、ログ圧縮、版の自動作成、接続中の権限再検証、ページの担当ノード決定・転送・ノード間配信 |
| `modules/app` | 起動・設定（環境変数）、ビルド済みフロントの配信 |
| `deploy/` | Dockerfile・Patroni/HAProxy設定（試験環境）と、VM構築用の設定ひな形（`deploy/vm/`） |
| `modules/shared` | バックエンドとフロントエンド(Scala.js)で共有する API の型（circe）。日時は `Timestamp`（JVM では `Instant`、JS では ISO 文字列） |
| `modules/web` | Scalactive(Scala.js)で書いた画面（`.st`）。Vue から移行中（下の「フロントエンド」） |
| `frontend/` | Vue 3 + TypeScript + Tiptap + Yjs（ページツリー、エディタ） |
| `proto/` | 同時編集 + 日本語IME 検証用プロトタイプ（検証済み） |

## 権限モデル
- ワークスペース権限（ACL / 既定権限）→ ページACLが上書き。ページ単位で `view` / `edit`。
- 対象ページから根に向かい、自分（本人または所属グループ）に一致する最初のエントリが採用される。同階層は最大権限。
- `inherit=false` のページは上位の権限を継承しない（設定者本人は自動でEditが付く）。
- `ADMIN_GROUPS` に含まれるグループ（IdPのグループ）の所属者は全ページ編集可。
- **ゲスト公開**: 編集権限のある人は、ページを公開リンク（`/s/<token>`）で未ログインの人に閲覧のみで公開できる。子ページを含めるかを選べる。
  `inherit=false` の子ページ（個別に閲覧制限したページ）とその下は公開に含めない。`PUBLIC_SHARING=false` で機能ごと無効化できる。

## 開発
```bash
docker compose -f docker-compose.dev.yml up -d --wait   # PostgreSQL+PGroonga (:54329), ScalaS3 (S3互換 :3900。初回はソースからイメージをビルド), Mailpit (SMTP :1025, 画面 :8025)
TEST_DATABASE_URL=jdbc:postgresql://localhost:54329/skiwi_test TEST_S3_ENDPOINT=http://localhost:3900 sbt test
```
`TEST_DATABASE_URL` を設定しないとDB結合テストはスキップされる。テストは開発用の `skiwi` ではなく `skiwi_test` を使うこと
（テストはデータを消さないため、開発用DBに試験用のワークスペースが溜まる）。`skiwi_test` は初回起動時に作られる
（既存の環境では `docker compose -f docker-compose.dev.yml exec db createdb -U skiwi skiwi_test`）。

**DBマイグレーション**（`modules/db/src/main/resources/db/migration`、Flyway）: スキーマを変えるときは新しい番号の `V<n>__…sql` を追加し、適用済みのファイルは書き換えないこと（起動時の検証で失敗する）。

## 起動
```bash
export DATABASE_URL=jdbc:postgresql://localhost:54329/skiwi DATABASE_USER=skiwi DATABASE_PASSWORD=skiwi
export OIDC_ISSUER=https://auth.example.com/application/o/skiwi/   # IdP の Issuer（`/.well-known/openid-configuration` の issuer と末尾スラッシュ込みで一致させる）
export OIDC_CLIENT_ID=... OIDC_CLIENT_SECRET=...
export PUBLIC_URL=https://skiwi.example.com                        # https の場合 Cookie に Secure が付く
export ADMIN_GROUPS=skiwi-admins                                   # 任意（カンマ区切り）
# export OIDC_GROUPS_CLAIM=groups                                 # 所属グループが入るIDトークンのクレーム名（既定 groups）
export S3_ENDPOINT=https://s3.example.com S3_BUCKET=skiwi S3_ACCESS_KEY=... S3_SECRET_KEY=...  # 未設定なら添付は無効
export MAX_UPLOAD_MB=100                                          # 任意
# メール通知（未設定ならメールは送らない）。SMTP_TLS: starttls(既定,587) | ssl(465) | none(25)
export SMTP_HOST=mail.example.com SMTP_PORT=587 SMTP_TLS=starttls SMTP_USER=... SMTP_PASSWORD=... MAIL_FROM=skiwi@example.com
# SCIM（任意）。設定すると /scim/v2 が有効になり、グループ所属はSCIMを正とする（ログイン時のgroupsクレームでは上書きしない）
export SCIM_TOKEN=$(openssl rand -base64 32)
# ゲスト向けの公開リンクを使わせない場合
# export PUBLIC_SHARING=false
# ゴミ箱の保存日数（既定30日。過ぎたら添付ファイルを含めて完全に削除）
# export TRASH_RETENTION_DAYS=30
# Webhook の送り先に http:// を許す（開発用。既定は https のみ）
# export WEBHOOK_ALLOW_HTTP=true
# リンクのカード（/api/unfurl）でプライベート・ループバックのアドレス（127.0.0.1・10.x・192.168.x など）も読み込む（既定は読み込まない）
# export UNFURL_ALLOW_PRIVATE=true
# draw.io の図のエディタ（既定 https://embed.diagrams.net）。社内に置いた draw.io（jgraph/drawio）を使うときに指定。空にすると図の編集を止める
# export DRAWIO_URL=https://drawio.example.com
# 外部サービスのトークンを暗号化する鍵（32バイトを base64。全ノードで同じ値）。未設定なら skea・skawau 連携は使えない
# export ENCRYPTION_KEY=$(openssl rand -base64 32)
# skea → skiwi の連携のクライアントの初期登録（任意。管理画面でも登録できる。まだ登録されていないときだけ使う）
# export OAUTH_CLIENT_ID=skea OAUTH_CLIENT_SECRET=$(openssl rand -base64 24) OAUTH_CLIENT_REDIRECT_URI=https://skea.example.com/api/integrations/skiwi/callback
sbt app/run
```

### 3ノード構成
各ノードに `NODE_ID`（一意な名前）、`NODE_URL`（他ノードから届くこのノードのURL）、`CLUSTER_SECRET`（全ノード共通、16文字以上）を設定する。
`DATABASE_URL` はPatroniの3台を並べ `targetServerType=primary` を付ける。構築・運用・バックアップは [docs/operations.md](docs/operations.md)。
```bash
scripts/ha-up.sh && (cd frontend && npm run test:ha)   # Docker上の3ノード環境と障害試験
```

### IdP 側の設定
OIDC に対応した IdP なら使える（`OIDC_ISSUER` の `/.well-known/openid-configuration` からエンドポイントを取得する）。
- クライアント: 機密クライアント（client secret あり）。トークンエンドポイントへは `client_secret_post` で認証する。
- Redirect URI: `${PUBLIC_URL}/auth/callback`
- Scopes: `openid` `profile` `email`
- グループ: IDトークンに所属グループ名の配列を入れる（既定のクレーム名は `groups`、`OIDC_GROUPS_CLAIM` で変更）。
  グループのクレームを出せない IdP では、SCIM で同期するか、グループによる権限・`ADMIN_GROUPS` を使わない。
- SCIMを使う場合は、OIDC の `sub` を SCIM の `userName` と同じ値（ユーザー名など）にする
  （skiwi はSCIMの `userName` とOIDCの `sub` を同一人物として突き合わせるため）。

#### SCIM（ユーザー・グループの同期）
- IdP の SCIM 2.0 プロビジョニング（プッシュ型）に、URL: `${PUBLIC_URL}/scim/v2`、Bearer トークン: `SCIM_TOKEN` と同じ値を設定する。
- IdPでユーザーを無効化・削除すると、skiwi 側でもログイン不可になり、セッションは即時失効、開いている編集画面も切断される。
- 対応範囲: Users / Groups の作成・取得・一覧（`eq` フィルタ）・置換(PUT)・PATCH・削除、ServiceProviderConfig。Bulk・ソート・ETagは非対応。

## 手早く試す（開発用）
```bash
scripts/dev-up.sh                              # DB・ScalaS3起動、フロントビルド、アプリ起動(:8080)
scripts/dev-session.sh "山田 太郎" user-1 skiwi-admins yamada@example.com   # Cookie値を出力（グループ・メールは任意）
```
送信されたメールは Mailpit（http://localhost:8025）で確認できる。SCIMも試す場合は `SCIM_TOKEN=dev-scim-token-123456 scripts/dev-up.sh`。
ブラウザで `http://localhost:8080/auth/callback` を開き、コンソールで `document.cookie="skiwi_session=<出力値>; path=/"` を実行してから `/` へ。

## エディタ
- **画像・ファイルの追加**: 画像の貼り付け（⌘/Ctrl+V。名前のないスクリーンショットには日時の名前を付ける）、ファイルのドラッグ＆ドロップ（落とした位置に、選んだ順で入る。
  画像は画像、それ以外はファイルのカード）、`/画像`・`/ファイル`。編集モードの本文の外に落としても、ブラウザがファイルを開いてページから離れることはない。
ページは**表示モード**で開く（誤操作で書き換えない。リンク・目次・開閉ブロックをそのまま使える）。右上の「✏️ 編集」または `E` キーで**編集モード**、「完了」で戻る。
新規作成したページと無題のページは編集モードで開く。編集内容は常に自動保存・同時編集される（モードは自分の画面の表示だけの違い）。

「/」でブロック挿入メニュー（見出し、リスト、ToDo、開閉ブロック、情報・注意・成功・エラー・メモのパネル、目次、引用、コード、表、画像、ファイル、埋め込み、数式、Mermaid、区切り線）。
- 一覧の最下部の「すべてのブロックを表示…」で、分類ごとの表から選べる（検索・↑↓・Enter で操作。「/」のあとに入力していた語で絞り込んだ状態で開く）。
- **パネル**: アイコンと背景色付きの囲み。左のアイコンをクリックしてアイコン・色の変更や解除。
- **目次**: 見出し（既定は見出し3まで）から自動で作られ、クリックでその見出しへ移動。
- **コード**: 右上で言語を指定（未指定なら自動判定）。コピーボタン付き。
文字選択で書式メニュー（太字、斜体、下線、取り消し線、コード、ハイライト、リンク）。画像・ファイルは貼り付け／ドラッグ＆ドロップでもアップロードできる。
Markdown風の入力（`# `、`- `、`1. `、`[] `、`> `、```` ``` ````）にも対応。
表の中にカーソルを置くと表の左に「⋮」ボタンが出て、クリックで表メニュー（行・列の追加/削除、セルの背景色、見出し行/列、セル結合、表の削除）。
背景色は複数セルをドラッグで選んでまとめて付けられる。列幅は境界線をドラッグ。
画像は左右・下角のハンドルをドラッグして大きさを変えられる（縦横比は維持）。画像をクリックすると「配置」メニューで左・中央・右寄せを選べる。
**ホワイトボード**: 「/」→「ホワイトボード」で、付箋・図形・矢印・手書き・文字・画像を自由に置けるボード（Excalidraw）をページに埋め込む。
- 同時編集できる（ページと同じ接続で同期。ほかの人のカーソルと名前も表示）。「⤢ 全画面」で大きく編集、下端のドラッグで高さを変える、「⤓ PNG」で画像として保存。
- 表示モード・ゲスト公開・版のプレビューでは閲覧のみ（移動・拡大はできる）。ボード内の文字はページの検索対象になる。
- 貼り付けた画像はページの添付ファイルとして保存する。
- 版の復元では、ホワイトボードの中身もその版の状態に戻る（開いているほかの人の画面にも反映）。
**@メンション**: 本文で「@」に続けて名前を入力すると、ユーザーを選んで挿入できる。保存されると、新しくメンションされた人に通知（画面内・メール）が届く（そのページを閲覧できる人だけ）。
**段組み**: 「/」→「段組み（2列）」「段組み（3列）」「段組み（列数を指定）」で、セクションを横に並べる（2〜12列）。
編集モードでは上部の帯で列数と幅の比（1:2 など。「比を指定…」で任意の比、合計12にすると12等分の目盛り）を変えられる。
列を減らすと、消える列の中身は残る最後の列の末尾へ移る。スマートフォンの幅では縦に積む。帯の「⠿ 段組み」をドラッグするとブロックごと移動。
**ToDo の担当者・期限**: ToDo リストの項目に @名前（または「/」→「担当者」）を書くとその人の担当、「/」→「期限」で期限の印（クリックで日付を変更）。
担当になった人はサイドバーの「✅ ToDo」で、すべてのワークスペースの自分のToDoを「期限切れ／今日・明日／これから／期限なし」に分けて見られる。
期限が今日・明日・過ぎた未完了のToDoは、担当者に1回だけ通知（画面内・メール）する（1時間ごとに確認。「今日」の基準は `TASK_TIMEZONE`、既定 Asia/Tokyo）。
**同期ブロック**: 「/」→「同期ブロックを作成」で、ほかのページに埋め込める範囲を作る。枠の「埋め込み用リンクをコピー」で得たリンクを別のページに貼り付けるか、
「/」→「同期ブロックを埋め込む」でページを選ぶと、読み取り専用で埋め込まれる（ページ全体も埋め込める）。元を直すと埋め込み先にも反映される（保存後、最長30秒ほどで表示が更新）。
埋め込みの中の埋め込みは1段まで。元のページを閲覧できない人には中身を表示しない。
**ラベル**: 編集モードでタイトルの下の「＋ ラベル」から付ける（「,」区切りで複数。大文字小文字の違いは同じラベル扱い）。
**被リンク**: ページの下部に「このページへのリンク」として、このページへリンクしているページを表示する（本文の保存時に更新）。
**ページへのリンク**: skiwi のページのURLを貼り付ける（または入力して空白を打つ）と、ページのアイコンとタイトルを表示するリンクになる。
タイトルは表示のたびに最新のものが出る（名前を変えても追従）。削除済み・閲覧権限のないページは「🔒 アクセスできないページ」と表示する。
「/」→「ページへのリンク」でページを検索して挿入することもできる。編集モードでは Ctrl/⌘+クリックで開く。
**ブロックのつまみ（⋮⋮）**: 編集モードでブロックに乗せると左に出る。ドラッグで移動、クリックでメニュー
（変換・文字と背景の色・複製・ブロックへのリンクをコピー・別のページへ移動・削除）。ブロックへのリンク（`#block-xxxx`）は `data-block-id` の属性で、
開くとそのブロックへスクロールして光らせる。別のページへの移動は、ブラウザから移動先のページに同時編集の接続をして末尾に足し（編集権限を確認）、
サーバーの圧縮要求にも答えてから元を消す（同時編集の中継では、サーバーは Yjs を解釈しないため）。
**色**: 書式メニューの「A」・ブロックのメニューで、文字の色・背景の色（10色。色の名前で保存し、ダークモードでは別の色で表示）。
**開閉見出し**: 「/」→「開閉見出し1〜3」（開閉ブロックに見出しの大きさを付けたもの）。
**絵文字**: 「:」+ 名前（日本語・ひらがな・英語）で候補を出す。
**画像のキャプション**: 画像の下の欄に説明を書ける。
**URL の貼り付け**: URL だけを貼ると「リンクのまま／カード／埋め込み」を選べる。カード（`/ブックマーク` でも作れる）は `/api/unfurl` で OGP・タイトル・アイコンを読む
（ログイン必須、1時間キャッシュ、リダイレクト3回・512KBまで、プライベート・ループバックのアドレスは `UNFURL_ALLOW_PRIVATE` がなければ読まない）。
埋め込みは YouTube・Vimeo・Figma・Google ドキュメント／スプレッドシート／スライド／ドライブ・Loom・Miro・CodePen・Spotify の共有 URL を埋め込み用に変える。
**ページ内のデータベース**: 「/」→「データベース（ページ内）」で、新しく作るか既存のデータベースを選んで本文に表示する（ビューはブロックごとに保存）。
**全幅表示**: 右上の「↔ 全幅」でページごとに本文を画面幅いっぱいにする（`page.full_width`。全員に効く）。
**パンくずリスト**: タイトルの上に親ページのたどりを表示する。
**draw.io の図**: 「/」→「draw.io 図」。diagrams.net の埋め込みモード（`DRAWIO_URL`、画面は `/api/client-config` で受け取る）を全画面の iframe で開き、postMessage でやり取りする。
保存は `xmlpng`（図の XML を埋め込んだ PNG）で書き出して添付ファイル（`図名.drawio.png`）にし、ノードには PNG の URL・題名・図の中の文字（検索・本文の文字用）を持つ。
開き直すときはその PNG から読み込む。`.drawio.png`・`.drawio` の貼り付け／ドロップ、取り込み（ZIP 内の `.drawio.png`・`.drawio`、Confluence の「図名.png」+「図名」）も図のブロックにする
（XML だけのものは `xmlSrc` に持ち、最初の保存で PNG にする）。
サイドメニューは上部の「«」で閉じ、左上の「☰」で開く（`⌘ + \` / `Ctrl + \` でも切り替え。開閉状態はブラウザごとに保存）。

## ワークスペース
- **作成**: サイドメニュー上部のワークスペース選択欄の一番下「＋ 新しいワークスペースを作成…」から。
- **名前の変更・共有設定・ページの取り込み・ゴミ箱・削除**: ワークスペース名の右の「⋯」から（編集権限が必要）。
  削除したワークスペースはゴミ箱に入り、中のページごと元に戻せる。
- **お気に入り**: サイドメニュー上部のワークスペース名の右にある「☆」で登録・解除（ユーザーごと）。お気に入りは一覧の上に「★ お気に入り」としてまとめて並び、トップページを開いたときも最初のお気に入りが開く。

## ヘッダ
画面上部に、左にロゴ（`/` へ戻る）、右に自分のアイコンを置く。アイコンを押すとメニュー（アイコンの変更・表示の明暗・使い方・
skea／skawau との連携・APIトークン・API の説明書・管理者向けの画面・ログアウト）が開く。サイドメニューを閉じているときは左に「☰」を出す。

**ユーザーのアイコン**: メニューの「🖼 アイコンを変更」で画像を選ぶと、ブラウザで真ん中を正方形に切り抜いて 256px に縮め（WebP、使えなければ JPEG）、
`PUT /api/me/avatar` で送る（PNG・JPEG・WebP、200KB まで。先頭のバイトで種類を確かめる）。DB の `user_avatar` に1人1枚。
`GET /api/users/{id}/avatar?v=…`（ログイン中なら誰のものでも。版付きは長くキャッシュ、`CSP: sandbox`）で配り、
ヘッダ・開いている人の表示（同時編集の awareness に URL を載せる。受け取る側はこの形の URL だけを使う）・コメントに出す。なければ名前の1文字を色付きの丸で出す。

## カスタムCSS（スタイル）
- **ページ**: ページ右上の「🎨 スタイル」。入力中はその場で見た目に反映される。「子ページ（その下の階層すべて）にも適用する」を外すと、そのページだけに効く。
- **ワークスペース**: ワークスペース名の右の「⋯」→「🎨 スタイル（カスタムCSS）」。ワークスペースの全ページに効く。
- 重ねる順: ワークスペース → 子にも適用する祖先ページ（上の階層から）→ そのページ。後のものほど優先される。ゲスト向けの公開ページにも効く。
- 安全のための制限（表示側で自動的に書き換え・除去し、編集画面に警告を出す）:
  - ページの表示エリア（タイトルと本文）の中だけに効く。`:root`・`html`・`body` は表示エリアに置き換わる。サイドバーや他の画面には効かない。
  - `@import`、外部の `url()`（`http(s)://` など）、`position: fixed` は使えない。`url()` は添付ファイル（`/api/attachments/…`）と `data:image` のみ。
  - 1つにつき20,000文字まで。設定できるのは編集者のみ（監査ログに残る）。

## 公開リンクの公開版・期間・URL・検索エンジン
共有画面の「🌐 ゲストに公開」で、公開リンクごとに設定する（その場で反映）。
- **公開する内容**: 「編集中の内容をそのまま公開する」（既定）か、「『公開』を押した時点の内容を公開する」。
  後者では公開範囲の各ページのタイトル・本文を公開版として保存し、ゲストにはそれを見せる（編集中の変更は見えない）。
  「現在の内容を公開」で公開版を作り直す。未反映の変更があると「⚠ 公開版に反映していない変更があります」と出る。
  公開後に削除・非公開にしたページは、公開版にあってもゲストには見せない。
- **公開期間**: 開始日時（予約。それまではゲストに「◯から公開されます」と案内）と終了日時。管理者の「公開中のページ」にも出る。
- **URL名**: `/s/<URL名>`（英小文字・数字・ハイフン、3〜64文字。全体で重複不可）で開けるようにする。トークンのURLも使える。
  子ページは、そのページの共有画面の「このページのURL名」で `/s/<URL名>/<ページのURL名>` にできる（ワークスペース内で重複不可）。
- **検索エンジン・OGP**: 公開ページのHTMLにタイトル・説明文（空欄なら本文の冒頭）・最初の画像・正規URLを埋め込む（チャット・SNSのリンク表示用）。
  既定では `noindex`。「検索エンジンに載せる」を選ぶと外し、`/sitemap.xml` に載せる（パスワード付き・期間外は載せない）。`/robots.txt` は `/s/` 以外を拒否する。
- **ゲスト向けの検索**: ゲスト画面のサイドメニューの検索欄で、ページ名に加えて本文も検索する（公開範囲・公開版の内容だけ。
  ひらがな／カタカナ・全角／半角・大文字／小文字・小さい文字・長音とハイフンの違いは無視）。一致箇所を強調した抜粋を出す。

## データベース（表・ボード・リスト・ギャラリー・カレンダー・タイムライン）
ページを編集モードにして、タイトルの下の「📊 データベースにする」を押すと、子ページを項目として一覧できるようになる
（最初は「状態（未着手・進行中・完了）」「担当者」「期限」の列と、表・ボード・カレンダーのビューが入る）。
- **列**: テキスト・数値・選択・複数選択・日付・ユーザー・チェック・URL。表の見出しをクリックして名前・種類・並び・選択肢（色）を変える。「＋」で追加。
- **ビュー**: 表（その場で値を編集。下の欄に名前を入れて Enter で項目を追加）、ボード（選択の列ごとに分け、カードをドラッグで移すと値が変わる）、
  カレンダー（日付の列で月表示。ドラッグで日付を変える。「＋」でその日の項目を追加）。ビューは複数作れる（タブのダブルクリック・「⋯」で名前の変更・削除）。
- **絞り込み・並べ替え**: 「⚙ 絞り込み・並べ替え」で条件（含む・が・より前／後・空 など。ユーザーは「自分」も選べる）と並び順をビューごとに保存する。上部の検索欄は名前と値をまとめて探す。
- 項目は普通のページなので本文も書ける。項目のページの上部に値が出て、そこでも変えられる。項目の権限はページの権限による
  （閲覧できない項目は出ない。閲覧のみの人のビューの変更はその画面だけ）。
- 「⚙」→「データベースをやめる…」で普通のページに戻せる（子ページと値は残る）。ページを複製すると、列・ビュー・値も複製する。
- **関連・集計**: 「関連」の列で、別の（または同じ）データベースの項目を指せる（例: 案件 → 顧客）。「集計」の列で、関連先の
  件数・値のある件数・合計・平均・最小・最大・チェック済みの割合を表示する（関連先の数値の列などを選ぶ。値は自動で計算）。
- **CSV**: ビューの「⋯」→「CSVで書き出し」（表示中の項目・列。Excel で開ける）／「CSVから取り込み」（1行目は列名。「名前」の列が項目名。
  同じ名前の列に値を入れ、ない列はテキストの列として追加。選択肢は足りない分を追加。日付は 2026/1/5 なども可。UTF-8・Shift_JIS。最大2000行）。
- **ビューの追加**: リスト・ギャラリー（カバーは本文の最初の画像か URL の列）・タイムライン（開始・終了の日付の列。ドラッグで移動・期間の変更）。
- **自動の列**: 数式（`prop("列名")`・四則演算・比較・`if`・日付の関数など。ブラウザで計算）、作成日時・更新日時・作成者・更新者、ID（接頭辞付きの通し番号。
  `page.props._seq` に保存し、`page_database.next_seq` で採番。データベースの API を通さずに作った項目も、一覧のときに番号を振る）。自動の列には値を書き込めない。
- **計算**: 表の下の行で、列ごとに件数・合計・平均・最小・最大などを表示（ビューごとに保存）。
- **グループ化**: 表・リストを選択・チェック・ユーザーの列で区切る。**サブ項目**: 項目の子ページを項目として扱い（親の下に開閉で表示）、API は `parentId` で作る。
- **フォーム**: ビューの「⋯」→「📝 フォーム」。公開の `/f/:token` で回答を受け、データベースの項目として作る（フォームを作った人の権限。トークンごとの送信回数制限）。
  必須の質問、ログインを求めて回答者をユーザーの列に記録する設定、受付の停止ができる。

## 自動化ルール
ワークスペースの「⋯」→「⚙ 自動化ルール」（編集権限が必要）で、「きっかけ」と「動作」を組み合わせる。
- **きっかけ**: ページの状態が変わった（変わった先の状態を指定できる）／ラベルが付いた／ページが作られた／データベースの値が変わった（列・値を指定）／
  データベースの日付になった（日付の列の◯日前・当日・◯日後。「状態が完了なら除く」などの条件。1時間ごとに確認し、同じ項目・日付には1回だけ）。
  対象を特定のページの下に絞れる。
- **動作**: 通知（ページの所有者・ウォッチしている人・指定した人・データベースのユーザーの列。画面内とメール）／外部への通知（Webhook）で送る／状態を変える／ラベルを付ける。
  文面に `{title}`（ページ名）・`{actor}`（操作した人）・`{date}`・`{status}` を使える。
- 動作で変えたページで、ほかのルールが続けて動くことはない。ルールごとに最後に動いた日時・回数・エラーを表示する。

## 受信用の Webhook（外部からページを作る）
ワークスペースの「⋯」→「📥 受信用の Webhook」で URL を作る（受け取り先のページの編集権限が必要）。URL に JSON を POST すると、作った人の権限で次を行う。
- **データベースに項目を追加**: `{ "title": "…", "text": "本文（改行で段落）", "values": { "列名または列ID": 値 } }`（選択肢は名前、日付は `2026-12-01`・`2026/12/1`、ユーザーはメールアドレスでも可）
- **子ページを作る**: `{ "title": "…", "text": "…" }`
- **コメントを付ける**: `{ "text": "…" }`（Slack 形式の通知もそのまま受け付ける）
- URL はトークンを含み、作成・作り直しのときだけ表示する。1分に60件・本文64KBまで。作った人が受け取り先を編集できなくなると止まる。無効にもできる。
- 本文はサーバーで同時編集用のデータ（Yjs）に変換するので、作られたページはそのままエディタで編集できる。

## 外部への通知（Webhook・Slack・Teams）
ワークスペースの「⋯」→「📣 外部への通知」（編集権限が必要）で、送り先と送る出来事を設定する。
- **出来事**: ページの作成（タイトルが付くよう1分待って送る）・更新（編集が落ち着いてからまとめて）・削除、コメント、ゲスト向けの公開（変更点のメモ付き）。
- **送り先の形式**:
  - **Slack**: Incoming Webhook のURL。
  - **Microsoft Teams**: チャネルのワークフロー「Webhook 要求を受信したらチャネルに投稿する」のURL（Adaptive Card で送る）。
  - **JSON**: `{ event, text, workspace, page: { id, title, url }, actor, … }` を POST する。`X-Skiwi-Signature: sha256=<HMAC-SHA256>` で、
    作成時に一度だけ表示する秘密の値による署名を確かめられる（`X-Skiwi-Event`・`X-Skiwi-Delivery` も付く）。
- 個別に権限を絞ったページ（「親の権限を引き継がない」にしたページとその下）の出来事は送らない。送信時点でも確かめ直す。
- 送れなかったものは間隔を空けて再送する（4xx は再送しない）。「テスト送信」と、最後の送信結果を設定画面で確認できる。送り先は https のみ（`WEBHOOK_ALLOW_HTTP=true` で http も可）。

## skea・skawau 連携（タスクID・ファイルのリンクの表示）
本文中の skea のタスクID（`SKEA-123` など）をリンクにしてタイトルと状態を横に出し、skawau のファイル・フォルダのリンク（`…/view/{ID}` など）にファイル名を出す。
取り決めは [docs/skea-integration.md](docs/skea-integration.md)・[docs/skawau-integration.md](docs/skawau-integration.md)。どちらも同じ仕組み（`IntegrationRoutes`。サービスごとの違いは `LinkedService`）。
- **設定（管理者）**: 画面右上の自分のアイコンのメニューの「外部連携」（`/admin/integrations`）で、連携先ごとに URL・client_id・client_secret（skea は対象のプロジェクトキーも）を入れる。画面に出る redirect_uri（`${PUBLIC_URL}/api/integrations/{skea|skawau}/callback`）を相手側に登録する。`ENCRYPTION_KEY`（32バイトの base64）が未設定なら機能は使えない（503）。
- **連携（各ユーザー）**: 画面右上の自分のアイコンのメニューの「🔗 skea と連携」「🔗 skawau と連携」→ 相手の許可画面（OAuth 2.0 認可コード + PKCE S256）→ 戻ると、読み取り専用のトークンを AES-GCM で暗号化して保存する（`integration_connection`）。state と code_verifier は DB に10分保存（複数ノード対応）。解除は相手の `/oauth/revoke` を呼んでから削除。
- **表示**: ProseMirror の decoration だけで行い、本文は書き換えない（`frontend/src/editor/SkeaTasks.ts`・`SkawauFiles.ts`、共通部分は `linkedDecorations.ts`）。コードブロック・インラインコードの中は対象外。閲覧中はクリックで開き、編集中は Ctrl/⌘+クリックか、横の表示のクリックで新しいタブに開く。skawau は、貼り付けたままの URL を閲覧中は隠して「📄 ファイル名」だけにし、文字を付けたリンクは文字のまま（マウスを乗せると名前）。未連携の人には何も足さない（skea はリンクだけ）。ゲスト向けの公開ページ・版のプレビューでは何もしない。
- **取得**: `POST /api/integrations/{skea|skawau}/lookup {keys}`（100件まで）で本人のトークンを使い、skea の `/api/tasks/lookup`・skawau の `/api/files/lookup` を呼ぶ。(サービス, ユーザー, キー) ごとに60秒キャッシュ。相手が 401 を返したら連携を消して `connected:false`。

### 逆向き: skea → skiwi（skea にページのタイトルを出す）
skiwi が OAuth 2.0 の認可サーバーになり、skea のタスクに書いた skiwi のページのリンクにタイトルを出す（取り決めは [docs/skea-integration.md](docs/skea-integration.md) の後半）。
- **登録（管理者）**: 同じ画面の「skea → skiwi」で client_id・client_secret（ハッシュだけ保存）・redirect_uri（完全一致）・表示名を入れる。環境変数 `OAUTH_CLIENT_ID`・`OAUTH_CLIENT_SECRET`・`OAUTH_CLIENT_REDIRECT_URI`・`OAUTH_CLIENT_NAME` でも登録できる（未登録のときだけ。`scripts/dev-up.sh` は開発用の値を入れる）。
- **認可**: `GET /oauth/authorize`（許可の画面。未ログインならログイン後に戻る。PKCE S256 のみ）→ `POST /oauth/token`（Basic 認証）。発行するのはそのユーザーの読み取り専用の API トークン「skea 連携」（期限なし。「APIトークン」の画面から解除できる。許可し直すと前のトークンは失効）。`POST /oauth/revoke`（RFC 7009）。
- **参照**: `POST /api/pages/lookup {ids}`（100件まで）。見られるページの id・workspaceId・title・icon だけを返す。読み取り専用のトークンでも使える。

## ページの複製
サイドバーのページの「⋯」（右クリック）→「⧉ 複製…」、またはページ右上の「⤓ 書き出し」→「複製」。
名前・複製先のワークスペース・置く場所（元のページのすぐ下／ワークスペースの直下）・子ページを含めるかを選ぶ。
- 本文・添付ファイル（実体も複製）・ホワイトボード（画像を含む）・ラベル・スタイル・ゲスト向けHTML・個別の共有設定を複製する。
  個別に権限を絞ったページは、複製した人が編集できるようにする。閲覧できない子ページとその下は複製しない。
- 一緒に複製したページへのリンク・同期ブロックの埋め込みは、複製したページに付け替える。コメント・版の履歴・公開リンク・所有者・状態は複製しない。

## 閲覧権限の申請
開けないページ（リンクの「🔒 アクセスできないページ」を含む）を開くと、閲覧／編集権限を申請する画面になる（理由を書ける）。
- ページの有無は申請者には分からない（存在しないページへの申請も同じように受け付け、誰にも通知しない）。
- 通知先: ページの所有者・作成者（編集できる場合）。いなければ編集できる人（最大10人）。画面内の通知とメール。
- 許可・却下は、通知の「閲覧（編集）を許可」「却下」ボタン、またはページの共有画面上部の「✋ 権限の申請」から。
  許可するとページの個別の共有設定に追加し、申請者に通知する（接続中の画面にもすぐ反映）。却下も通知する（ページ名は出さない）。

## ページの保護
ページ右上の「🔒 保護」で、そのページを編集できる人を、保護した人・所有者・指定した人だけにする（ほかの編集者は閲覧のみ。共有設定は変えない）。
理由はページの上部に表示し、サイドバーのページ名に🔒が付く。保護の解除・変更は、保護中も編集できる人と管理者ができる。規程や確定した手順書の誤編集を防ぐ。

## 期限付きの権限
共有設定の一覧で、ユーザー・グループごとに期限の日付を付けられる（その日の終わりまで。空欄で無期限）。閲覧権限の申請を許可するときも、
期限（1週間・1か月・3か月）を選べる。期限を過ぎると権限の判定に使わず、1分以内に自動で外して、開いている画面にも反映する。ワークスペースの共有も同じ。

## ページの所有者・状態
タイトルの下の「📌 状態」（下書き／レビュー中／公開済み／廃止）と「👤 所有者」で設定する（編集者のみ）。状態はサイドバーのページ名の横にも出る。
検索の絞り込み（⚙）で状態・「自分が所有者のページ」を指定できる。

## 開いている人の表示

## ページの並べ替え・お気に入り
- サイドバーのページはドラッグ＆ドロップで並べ替え・移動できる（行の上端・下端に落とすと前後、中央に落とすと子ページ）。
- 別のワークスペースへは、ページの「⋯」（右クリック）→「別のワークスペースへ移動…」で子ページごと移せる（移動先の権限が適用される）。
  古いURL・リンクで開いても、移動先のワークスペースで開き直す。
- 「⋯」→「🩺 点検」で、ワークスペースのページを点検する（見えるページだけ）。
  - **リンク切れ**: 削除・存在しない・閲覧できないページへのリンクや埋め込み。
  - **孤立ページ**: ほかのページの本文から一度もリンクされていないページ（既定では最上位・子ページのあるページを除く）。
  - **更新されていないページ**: 本文・タイトルの最終更新が 3か月／6か月／1年／2年 より前のページ（「廃止」は除く）。最後に編集した人・所有者も出す。
- **一括操作**: サイドバーのページを ⌘/Ctrl＋クリック（追加・解除）、Shift＋クリック（範囲）、または「⋯」→「☑ 選択」で選ぶと、
  サイドバーの下に操作欄が出て、まとめて **移動**（ページの下・ワークスペースの直下・別のワークスペース）・**ラベル**（付ける／外す）・**所有者**・**状態**・**削除** ができる。
  ページごとに権限を確かめ、できなかったページは理由を表示する。選んだページの子孫も選んでいる場合は、親と一緒に移動・削除する。Esc で選択を解除。
- ページ右上の「☆ お気に入り」で、サイドバー上部の「★ お気に入り」に並ぶ（すべてのワークスペースのページ・ユーザーごと）。

## 検索
サイドメニューの検索欄で、ページ（タイトル・本文・添付ファイルの中身）とワークスペース名を検索する。検索欄の下で範囲を「このワークスペース／すべて」から選ぶ。
- **添付ファイルの中身**: PDF（PDFBox）・.docx・.xlsx・.pptx（ZIP 内の XML を StAX で読む）・OpenDocument・テキスト（UTF-8 / Shift_JIS）・HTML から文字を取り出し、
  `attachment_text`（PGroonga 索引）に保存する。アップロード直後に裏で取り出し、残り（既存の添付・失敗で漏れたもの）は1分ごとのループで順に処理（同時2件、1件2分・50MB・100万文字まで、
  展開後200MBまで）。失敗・対象外も状態（error / unsupported / too_large / empty）を記録して再試行しない。検索では、本文で見つからなかったページのうち、
  いまも本文に ID がある添付ファイルの中身で見つかったものを、`attachment`（ファイル名・URL）と中身のスニペット付きで本文の結果の後ろに並べる。
- 検索欄の右の「⚙」で絞り込み: ラベル、更新日（1週間・1か月・1年以内）、自分が作成したページ。語を入れずに絞り込みだけでも一覧できる。
- ひらがな／カタカナ、全角／半角（半角カナを含む）、大文字／小文字、小さい文字（ゃ・ゅ）、長音（ー）とハイフンの違いは無視する。英単語の途中からでも一致する。
- 語がそのまま含まれなくても、表記が近ければ「あいまい」の印付きで後ろに並ぶ（誤字・表記ゆれ。検索語の2文字ずつの組の半分以上が含まれるもの）。
- 空白で区切った複数の語はすべてを含むもの（AND）。漢字の読み（例:「ぎじろく」で「議事録」）は扱わない。
- 共有設定のユーザー・グループ検索も、ひらがな／カタカナ・全角／半角の違いを無視する。

## ページの機能（右上）
- **アイコン・名前の変更、削除**: サイドバーの各ページの「⋯」から（名前はダブルクリックでも変更できる）。ページ上部のアイコンからも変えられる。
- **ウォッチ**: 他の人の更新・コメントを通知（画面内とメール）で受け取る（作成者は自動でウォッチ）。「🔔」から受け取る内容を選べる。
  - 「本文の更新」「コメント」をそれぞれ選べる（例: コメントだけ受け取る）。
  - 「子ページも含める」にすると、その下のすべてのページの通知も届く。子ページに個別の設定があればそちらを優先する。
  - 本文の更新は、編集が5分止まったら、最長でも30分ごとに1通にまとめて送る。
- **履歴**: 版の一覧・プレビュー・手動保存（ラベル付き）・復元。編集が続くと約10分ごとに自動で版が残る。復元前の状態も版として残る。
- **共有**: ユーザー・グループ単位で閲覧/編集を付与。新しく共有した相手にはメール通知。ワークスペースの共有はサイドバー上部の👥から。

  公開リンクには**公開期間**（開始・終了の日時）と**パスワード**を設定できる。パスワードは10分間に10回まで試せる。
  共有画面の「👀 このページを閲覧・編集できる人」で、継承・グループを展開した実際の閲覧者・編集者と、その理由（どの共有設定によるか）を確認できる（編集者のみ）。
  管理者は画面右上の自分のアイコンのメニューの「公開中のページ」で、公開中のページの一覧（期限切れ・パスワードの有無）を確認し、停止できる。
- 画面右上の自分のアイコンのメニュー: **APIトークン**（発行・失効）、**API の説明書**、**監査ログ**（管理者のみ）。

## MCP（AI のツールから使う）
`POST /mcp` が MCP（Model Context Protocol）のサーバーになっている（Streamable HTTP。応答は JSON で、SSE は使わない）。
認証は API トークン（`Authorization: Bearer skiwi_…`）だけで、権限・読み取り専用のトークン・監査ログは REST API と同じ
（各ツールは REST API をそのトークンで内部から呼ぶ。`modules/api/.../McpRoutes.scala`）。
```bash
claude mcp add --transport http skiwi https://skiwi.example.com/mcp --header "Authorization: Bearer skiwi_..."   # Claude Code の例
```
- ツール: `get_me`・`list_workspaces`・`list_pages`（親子を字下げした一覧）・`search`・`get_page`（本文を Markdown で）・`get_backlinks`・
  `create_page`（本文は Markdown）・`replace_page_content`・`append_to_page`・`replace_section`（見出しの節）・
  `update_page`（タイトル・アイコン・状態）・`move_page`・`delete_page`（ゴミ箱へ）・`set_labels`・
  `list_comments`・`add_comment`・`get_database`・`add_database_rows`・`update_item_values`・`list_my_tasks`
- 本文の書き換えは REST API の `POST /api/pages/{id}/content`（下の「本文の書き換え」）で行う。
- 本文の Markdown 化はバックアップと同じ `MarkdownExport`（画面の書き出し `frontend/src/editor/markdown.ts` と同じ書き方。片方を変えたらもう片方も直す）。

## 本文の書き換え（API）
`POST /api/pages/{id}/content` に `{ "mode": "replace" | "append" | "replace_section", "markdown": "…", "heading": "…" }` を送る（編集権限が要る）。
- `replace` は本文をすべて、`replace_section` は `heading` と同じ文字の見出しから、同じか上の階層の次の見出しの手前までを置き換える。`append` は末尾に足す。
- 置き換える前の本文は版（ラベル「API で本文を変える前」）として残る。開いている人の画面にもそのまま反映される。
- 対応する Markdown: 見出し・段落・箇条書き・番号付き・ToDo（入れ子も）・引用・コード・mermaid・区切り線・表・画像だけの行、
  行内の太字・斜体・取り消し線・コード・リンク・`<u>`・`<mark>`・URL（`MarkdownParse`）。
- 仕組み: サーバーが Yjs の状態（スナップショットと更新ログ）を読み、項目の並びを Yjs と同じ規則（YATA）で再現して、
  今の本文を y-prosemirror と同じ読み方で JSON にする（保存待ちの編集も含む）。そのうえで、消すブロックの削除と新しいブロックの挿入だけの
  update を作る（`modules/api/.../skiwi/ydoc`）。その update はクライアントの編集と同じく保存・配信する（`Collab.injectUpdate`）。
  触らなかったブロックや、同時に編集している人の変更はそのまま残る。
- 制約: Markdown で表せないブロック（データベース・ホワイトボードなど）は、置き換える範囲に入れると消える。
- 試験: `YdocSpec` は、本物の Yjs（`frontend/test/yjs-check.mjs` を node で動かす）で複数人が同時に編集した文書を作り、
  並びの再現・本文の JSON・作った update の結果を突き合わせる（node と `frontend/node_modules` がなければ飛ばす）。

## 定期バックアップ（管理者）
ワークスペースの「⋯」→「💾 定期バックアップ」で、毎日決まった時刻にワークスペースのすべてのページを ZIP にして、添付と同じオブジェクトストレージ（`backups/`）に保存する。
- 中身は「書き出し → ZIP」と同じ形（フォルダ構成の Markdown・`attachments/`・`.excalidraw`）で、そのまま「取り込む」で戻せる。
  加えて `skiwi-backup.json` に、ページの親子・本文（JSON）・ラベル・データベースの定義と値・添付の一覧を入れる。
- 残す世代の数を決められる（古いものから消す）。「今すぐバックアップ」・ダウンロード・削除もできる。権限を絞ったページも含むので、管理者だけが扱える。
- 複数ノードでも同じ回を重ねて作らない（10分ごとに確認）。

## API（抜粋）
APIトークン（画面の「APIトークン」で発行）を `Authorization: Bearer <token>` で送る。権限は発行したユーザーに準じ、`read` スコープはGETのみ。
```bash
curl -H "Authorization: Bearer $TOKEN" https://skiwi.example.com/api/pages/<id>/content   # 本文(JSON)と平文
```
